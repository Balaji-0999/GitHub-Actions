01

Developer

You write or modify your portfolio code and push it to the main branch.

git push origin main
02

Trigger

GitHub detects the push and automatically starts your workflow.

on → push → branches: [main]
03

Runner

GitHub creates a temporary Ubuntu machine where all your workflow steps execute.

runs-on: ubuntu-latest
04

Deployment

Your website files are packaged into an artifact and then deployed to GitHub Pages.

upload → deploy
Source Code

Your Workflow

This is the workflow that powers the deployment.

.github/workflows/deploy.yml 
name: portfolio

on:
    push:
        branches: [main]

    workflow_dispatch:

permissions:
    pages: write
    id-token: write
    contents: read

jobs:

    deploy:

        runs-on: ubuntu-latest

        environment:
            name: github-pages
            url: ${{ steps.deployment.outputs.page_url }}

        steps:

            # Get portfolio source code

            - name: Checkout code
              uses: actions/checkout@v4

            # Configure GitHub Pages

            - name: Setup GitHub Pages
              uses: actions/configure-pages@v4

            # Package static website files

            - name: Upload static files
              uses: actions/upload-pages-artifact@v4
              with:
                  path: "."

            # Deploy artifact

            - name: Deploy to GitHub Pages
              id: deployment
              uses: actions/deploy-pages@v4
Security

Permissions Explained

These permissions tell GitHub what your workflow is allowed to do.

📄 contents: read Allows the workflow to read your repository files.
📦 pages: write Allows the workflow to publish your website to GitHub Pages.
🔐 id-token: write Allows GitHub's deployment system to use an OIDC identity token.
Execution

What Happens Internally?

Let's break the workflow down step-by-step.

1. GitHub detects your push

You push code to the main branch. The push event matches your workflow trigger.

2. GitHub creates an Ubuntu runner

GitHub starts a temporary virtual machine using ubuntu-latest.

3. Checkout code

actions/checkout@v4 downloads your repository code into the runner.

4. Configure GitHub Pages

actions/configure-pages@v4 prepares the GitHub Pages deployment environment.

5. Create Pages artifact

upload-pages-artifact@v4 packages the files from the specified path into a deployable artifact.

6. Deploy

actions/deploy-pages@v4 takes that artifact and publishes it to GitHub Pages.

7. Deployment URL

The deployment step exposes the resulting Pages URL through steps.deployment.outputs.page_url.

Environment

Why is this here?

Your environment connects the job with GitHub Pages.

environment: github-pages

The deployment job is associated with the github-pages environment.

name: github-pages
url: ${{ steps.deployment.outputs.page_url }}
